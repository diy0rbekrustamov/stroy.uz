# Дизайн и загрузка STROY UZ

## Что изменено

- Страницы загружаются отдельно через React.lazy и Suspense. Все существующие маршруты сохранены; добавлены состояния загрузки, ошибки и 404.
- Удалён неиспользуемый внешний CSS Font Awesome. SVG-иконки проекта сохранены.
- Изображения доставляются как WebP; четыре основных товара имеют версии 400 и 800 пикселей и srcSet. Исходные PNG сохранены.
- Пять схематичных товарных SVG заменены студийными 3D-иллюстрациями. Для строительства, ремонта и инженерных работ созданы три отдельные сцены. Услуги одной категории используют общую иллюстрацию, а не изображение выполненной работы.
- Hero очищен от встроенной подписи через imagegen; удалены скрывавшие подпись CSS-прямоугольники в hero и формах входа.
- ShopImage показывает нейтральную коробку при отсутствии/ошибке изображения, вместо случайного товара. Поддержаны RU/UZ/EN.
- Каталог кешируется на 30 секунд, одновременные запросы объединяются; событие stroy-catalog сбрасывает кеш после изменений продавца. При ошибке сервера каталог явно обозначен демонстрационным.
- Исправлены ссылки «Все категории» и «В каталог». Модальное окно блокирует прокрутку фона, удерживает фокус и возвращает его при закрытии. Добавлены фокус клавиатуры и сдержанный hover карточек с учётом reduced-motion.

## Измерения сборки

- Основной JS-файл: около 635 → 271 КБ (без gzip). Это размер входного файла, а не всей загружаемой страницы: общие модули загружаются отдельно.
- Четыре товарных PNG: суммарно около 8,75 МБ → 179 КБ для WebP 800 px или 55 КБ для набора миниатюр 400 px. Браузер выбирает размер с учётом ширины и плотности экрана.
- Lighthouse не запускался; численных оценок Core Web Vitals нет.

## Проверка

Сборка и 18 существующих тестов прошли, включая API, маршруты, формы, каталог, услуги, товары и RU/UZ/EN. Lint: без ошибок, три прежних предупреждения Fast Refresh/React Hook Form. git diff --check: без ошибок.

В браузере проверены главная и каталог на desktop; на ширине 390 px — каталог, услуги, товар, вход, регистрация, восстановление пароля, корзина, кабинет и 404. Горизонтального переполнения и ошибок загрузившихся изображений не обнаружено. Это выборочная проверка, а не исчерпывающее тестирование всех сочетаний устройств и данных.

## Приоритеты следующего этапа

1. Для публичного запуска настроить внешний PostgreSQL, резервные копии, HTTPS, SMTP для восстановления пароля и мониторинг ошибок. Локальный API запускается через npm run api:local, frontend — npm run dev.
2. Заполнить реальные контакты, правила доставки/возврата, юридические документы и проверенные данные продавцов. Сейчас часть информационных разделов демонстрационная.
3. Для реальных товаров использовать фотографии продавцов и галерею нескольких изображений. Сгенерированные иллюстрации не подтверждают внешний вид конкретного товара или портфолио исполнителя.
4. Перед ростом каталога перенести фильтрацию/сортировку/пагинацию на сервер; сейчас клиент подгружает весь набор страниц API (с ограничением).
5. Затем добавить модерацию объявлений, проверку почты, отзывы только после завершённого заказа, уведомления о статусах. Онлайн-оплату подключать после выбора провайдера и согласования бизнес-процесса.

Промпты и пути изображений: [generated-assets.md](generated-assets.md). Пересоздание WebP: scripts/optimize-assets.py (Python + Pillow); не требуется для обычного запуска Node/Vite.
