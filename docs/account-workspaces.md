# Кабинеты покупателя и продавца

## Страницы

- `/account` — заказы покупателя, поиск по номеру/названию и фильтр активных/закрытых заказов.
- `/account?section=requests` — заявки на услуги и аренду.
- `/account?section=profile` — имя, телефон, адрес по умолчанию.
- `/seller/overview` — реальные количества товаров, новых заказов и заявок, черновики и товары без остатка.
- `/seller` — управление товарами; `/seller/services` и `/seller/rentals` — услуги и техника.
- `/seller/orders` — поиск, фильтры статусов, обработка заказов и заявок, выдача ссылки водителю.
- `/seller/profile` — контакты и название магазина.

Адрес сохраняется в базе и подставляется в checkout; изменить его для конкретного заказа можно при оформлении. Избранное и корзина используют существующее хранилище браузера. Пользовательские названия и адреса сохраняются как введены, интерфейс переведён на RU/UZ/EN.

## API и миграции

`PATCH /api/auth/profile` требует сессию и CSRF. Разрешённые поля: `name`, `phone`, `address`, `storeName`. Изменение роли, email и чужого профиля через этот метод невозможно. Для продавца название магазина обязательно. Телефон здесь — контакт, а не подтверждённый номер.

Миграция `004_profile.sql` добавляет адрес в `users`. Общий запуск API применяет миграции; миграции доставки и индексов каталога сохранены обе.

Для локальной работы: `npm run api:local` и `npm run dev:web` в двух терминалах. `npm run dev:local` запускает существующий командный сценарий с локальной БД. По умолчанию API ожидает origin `http://127.0.0.1:5173`; при другом порте задайте согласованный `APP_ORIGIN`. Не используйте порт другого проекта.

## Границы готовности

Сохранение профиля и управление предложениями/заказами связаны с API. Онлайн-оплата, подтверждение телефона и отправка почты требуют отдельных подключений. Ссылка восстановления использует существующий сервис, а не имитацию отправки. Обзор магазина не выдаёт сумму заказов за полученную выручку.

Изменения текущего слияния разрешены локально; коммит и push не выполнялись. Для ревью: проверить покупателя и продавца на мобильном экране, редактирование профиля, пустые результаты поиска, отказ API и переход к карте заказа.
